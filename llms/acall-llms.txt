# Acall

> Acall Inc. (アコール株式会社, Tokyo and Kobe, founded 2010) builds the Acall / WorkstyleOS workplace
> platform — visitor reception, meeting-room booking, free-address desk (spot) reservation, entry-gate
> integration and multi-tenant building management for hybrid workplaces, used by 7,000+ organizations.
> Acall publishes a REST "Acall Public API" (v1, HTTP bearer, 13 operations) plus an outbound webhook
> surface. This file was generated by API Evangelist from Acall's own public artifacts; Acall does not
> publish an llms.txt of its own.

## Read this first

- API access is **not self-serve**. A token is issued only after a request through the Acall contact form
  with 「API利用希望」 in the body, and the API is **not available on the multi-tenant plan**.
- The API is **beta**. There is no published versioning policy, no SLA, and no deprecation policy.
- The published OpenAPI declares **success responses only** — no 4xx or 5xx is described for any operation.
- There is **no idempotency mechanism** on the three write operations.
- There are **no published rate limits** and no rate-limit response headers.

## APIs

- [Acall Public API](https://www.workstyleos.com/publicapi/index.html): REST v1 at
  `https://api.workstyleos.com/v1/`. Workers, facilities, appointments/internal meetings, entry-gate access
  logs, workspace spots, and workspace reservations. Bearer token auth, applied document-wide.

## Specs

- [OpenAPI 3.0.0](openapi/acall-public-api-openapi.yml): 13 operations, 10 paths, 24 component schemas.
- [Harvested original](openapi/_original/acall-public-api-openapi-original.json): the spec exactly as Acall
  serves it inside its Redoc reference bundle.
- [OpenAPI Overlay](overlays/acall-public-api-overlay.yaml): API Evangelist annotations (credential
  issuance, reversal operations, verified server).

## Operations

Read-only: `getUsers`, `getUser`, `getFacilities`, `getFacility`, `getEvents`, `getEvent`, `getGateLogs`,
`getSpots`, `getSpotReservations`, `getSpotReservation`.
Write: `postSpotReservation`, `putSpotReservation`, `deleteSpotReservation` — workspace reservations are the
only writable resource.

## Events

- [Webhook catalogue](asyncapi/acall-webhooks.yml): three triggers (appointment/internal meeting created,
  updated, deleted), configured per tenant in Acall Portal, with an optional signature-verification token
  and a test-send facility. No AsyncAPI document and no published payload schema. Does **not** fire for
  repeat-booking, CSV upload, or Acall Meeting.

## Semantics

- [Conventions](conventions/acall-conventions.yml): limit/offset paging with no envelope, freeword search,
  `starting_at`/`ending_at` time filters, `root_spot_id` scoping, idempotency `none`, reversibility
  `documented`.
- [Authentication](authentication/acall-authentication.yml): HTTP bearer, out-of-band token issuance,
  observed RFC 6750 challenges.
- [Error behaviour](errors/acall-problem-types.yml): probed, not published — plain-text bodies.
- [Data model](data-model/acall-data-model.yml): 6 entities, 7 embedded types, 9 relationships.
- [Rate limits](rate-limits/acall-rate-limits.yml): none published, none observed.

## Not available

No SDKs or client libraries in any language. No CLI. No MCP server. No A2A agent card. No GraphQL. No
gRPC/Protobuf. No WSDL. No Postman collection. No AsyncAPI. No `/.well-known/` discovery document on any
Acall host. No sandbox or test credentials beyond the webhook test-send. No published bug-bounty or
vulnerability-disclosure program.
